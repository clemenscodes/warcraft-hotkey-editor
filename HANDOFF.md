## What got done (all verified in-browser via Playwright)

### 1. Header composition — renamed & restructured to match `COMPONENTS.md`
- `Header` is now **pure layout** — no props, no hook, no data. It only places three children.
- Directory = render tree throughout. Old names gone:
  - `header_layout_slot` → **`grid_layout_button_host`** (host owns the centered/laptop-only box)
  - `header_actions` → **`toolbar`** (now a `<nav>`, always visible)
  - `header_toolbar` → **`toolbar/components/toolbar_actions`** (a `display:contents` wrapper)
    which holds **`inline_actions`** (the file-button row, `hidden`→`laptop:flex`) **and**
    **`burger_menu`** (mobile/tablet only). Burger is a subcomponent of the toolbar actions.
  - `header_brand` → **`brand`** (prefix dropped), now nested under **`brand_host`** (see §4).
  - `collisions_button` → nested under **`collisions_button_host`** (host = container, see §5).
- Current header tree:
  ```
  header/                       <header>, pure layout
  ├─ brand_host/                (cqi container for the wordmark)
  │   └─ brand/                  Brand (self-sources its home-nav onclick)
  │       ├─ brand_decoration_leading/   → shared/brand_decoration_host → brand_decoration
  │       ├─ brand_title/
  │       └─ brand_decoration_trailing/  → shared/brand_decoration_host → brand_decoration
  ├─ grid_layout_button_host/    → grid_layout_button (presentational)
  └─ toolbar/                   <nav>
      ├─ collisions_button_host/ → collisions_button (presentational)
      └─ toolbar_actions/       (display:contents)
          ├─ inline_actions/     undo/redo/upload/templates/system/resolve/preview/export/help + shared/toolbar_button
          └─ burger_menu/
  ```

### 2. Prop-drilling eliminated (the big architectural win)
The header used to thread `loaded_keys` / `upload_status` / `grid_layout` down through
`Header → Toolbar → ToolbarActions → InlineActions` into buttons that mostly didn't need the
whole document. **Now the header threads no data.** Each button self-sources the minimal thing
it needs from context, via its own host — the `resolve_button` pattern applied everywhere:
- `CollisionsButtonHost` reads `CustomKeysService` + `grid_layout` (context) + nav, computes the
  `CollisionSummary`, and hands the presentational `CollisionsButton` only `{ summary, onclick }`.
- `UploadButton` self-sources `CustomKeysService` + `upload_status` (context) and imports through
  a new sanctioned service command **`CustomKeysService::import_overlay`** (keeps the wall: R4/R7 —
  the renderer never sets the keys signal itself).
- `BurgerMenu` needs no `CustomKeys` at all now; the download serialization moved to a shared
  **`DownloadInfoDialogHost`** (`components/dialogs/info_dialogs/download_info_dialog_host/`), which
  both the burger and the `ExportButton` render with just an `open` signal (dedups the old
  duplicate serialization).
- `Brand` self-sources its return-to-editor onclick from `ViewNavigationContext` (its own `use_brand`).
- **Enablers:** `workbench.rs` (`app/hooks.rs`) now `use_context_provider`s `grid_layout` and
  `upload_status` (appended last so the load-bearing hook order is untouched; other consumers keep
  their props).

### 3. Brand decoration — cqi
`shared/brand_decoration_host` is the cqi container that owns the flourish box; the `brand_decoration`
img is `w-[100cqi] h-auto` (fills, aspect preserved → the old mobile squish is gone).

### 4. Brand "one SVG" scaling
`BrandHost` is the container-query context. Title (`text-[length:5cqi]`), gap (`gap-[2.2cqi]`) and the
two decoration hosts (`w-[11cqi]`) are all `cqi` off the host → the whole wordmark scales as one
drawing, so the title never truncates. Desktop looks great.

### 5. Toolbar buttons — cqi, done right
- `CollisionsButtonHost` is the **container** (`[container-type:inline-size]` + box size per band:
  `w-[5rem]` laptop+, `w-9` mobile/tablet). `CollisionsButton` fills it (`size-full`) and its chrome
  is `cqi` → scales as one drawing across 80px (desktop) and 36px (mobile). Border is tuned per band
  to land on 1px (`1.25cqi`@80px via BASE, `2.8cqi`@36px via mobile/tablet); radius/icon/badge/ring
  scale uniformly.
- `BurgerMenu` is single-size (36px, hidden laptop+) → **fixed px** chrome (nothing to scale). Radius
  matched to collisions (`rounded-[5.4px]` == 15cqi@36px), icon `w-4`.

## Remaining TODO (next session) — the header is NOT finished

The user's explicit next steps, in order:

### A. Replace brand `flex-auto` with a **fixed width per viewport band**  ← do this first
`brand_host/style.rs` currently uses `mobile:flex-auto` / `tablet:flex-auto` to fill the space beside
the toolbar, and `laptop:w-[clamp(11rem,42vw,48rem)]` on laptop+. **`flex-auto` scales badly on tablet**
(the brand blows up far too large). Decision: drop the flex-auto approach. Define a **fixed `w-[…]` per
band** on `brand_host` (mobile, tablet, laptop, desktop, qhd, uhd) and be done. Pick each band's width
so the wordmark is well proportioned at that viewport; the cqi interior then scales to whatever fixed
width you give it.
- Note: on mobile the toolbar was shrunk (collisions/burger 44→36px, `toolbar` gap `gap-1`) precisely
  to free brand width — keep that in mind when choosing the mobile brand width.

### B. Convert `GridLayoutButton` to cqi
`grid_layout_button/style.rs` is still fixed rem (`h-24 px-8 gap-4 text-[2rem] rounded-[12px]` etc.).
Convert it to the same self-scaling pattern: `GridLayoutButtonHost` becomes the container
(`[container-type:inline-size]` + box size — it already owns the centered/laptop-only box), and the
button expresses its interior in `cqi`. **Gotcha (see below):** keep `[container-type]` on the *host*
and the cqi chrome on the *button*, or the button's own border/radius resolve against the viewport.

### C. Convert the **whole header** to cqi
Make the header itself a container and express its own layout (paddings, gaps, min-height, grid
column sizing) in `cqi`/viewport units so the entire bar — brand, center button, toolbar — scales
coherently per viewport. This is the endgame: header perfect on every viewport.

## Critical gotchas learned this pass (read before touching cqi)

1. **`text-[Ncqi]` silently does nothing.** Tailwind can't infer that `cqi` is a length for the
   `text-` utility (font-size vs color ambiguity), so it drops the rule and the font stays 16px.
   Use the type hint: **`text-[length:Ncqi]`**. (Width/gap/border take cqi fine — only `text-` needs it.)

2. **`container-type:inline-size` applies cqi to an element's DESCENDANTS, not to itself.** An
   element's *own* `border`/`border-radius`/`box-shadow` written in `cqi` resolve against its nearest
   *ancestor* container — and if there is none, against the **viewport** (that is how a 2.8cqi border
   became `2.8% × 375px = 10.5px`). Fix: the two-layer pattern used by `ToolbarButton`
   (`toolbar_button` container + `toolbar_button_surface` chrome) and now by collisions
   (`CollisionsButtonHost` container + `CollisionsButton` chrome): **container-type on the outer/host,
   cqi chrome on an inner child.** This is exactly why `COMPONENTS.md` says "the Host doubles as the
   leaf's container."

3. **Sub-pixel borders.** A pure-cqi border goes below 1px on small buttons (`1.25cqi`@36px = 0.45px →
   invisible at DPR 1). Do **not** hack with `max(1px, …)` — that freezes the value and breaks the
   linear scaling. Clean options: per-band coefficient tuned to 1px at each band's fixed size (what
   collisions does), or plain fixed px for a genuinely single-size element (what burger does).

4. **Do not use `flex-auto` to size a cqi container** — the width becomes "all remaining space", which
   is unpredictable per viewport (the tablet blow-up in §A). Give cqi containers a definite width
   (fixed per band, or a `clamp()`), so cqi resolves against something intentional.
